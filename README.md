# 探寻AI Coding代码最佳规范落地

本库主要是用于对 AI Coding 在项目目录结构、方案、模块等规范的研究，试图寻找一个相对完美的解决方案，既能够保证AI代码质量又能减少提示词数量以节约 token 量。

目前，库中会存在多种场景的规范且并不是最优解，收集相对多的数据资料做为经验源，然后通过具体的项目实践来确认最终推荐规范。从而形成以`_RECOMMEND`的最终推荐规范。

## 基于功能的规范（CLAUDE开头）

以基于 `CLAUDE` 为平台的规范，涵盖了前端、后端、数据、React、React组件等。目的是写出规范化的高质量代码

## AI_Specification_As_Code

SaC（规范即代码），是为了解决 AI 落地代码时，只是把“最终代码”写进了文件，但那些关于“为什么这么写”、“系统架构设计”、“模块依赖关系”的方案灵魂（方案信息），要么留在了 AI 工具的 History/Cache 默认缓存里，要么随着对话刷新直接丢了。导致项目一旦进入维护期或需要变更，新的 AI 或开发根本找不到完整的“方案全周期全景图”，无法实现闭合的同步。
